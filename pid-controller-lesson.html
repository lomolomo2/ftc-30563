PIDController: A Robot Correction Helper

A 7th-grade friendly lesson that explains proportional, integral, and derivative control with simple math diagrams.

1. What Is This Class?

PIDController is a helper class. It does not directly move a motor. Instead, it calculates a number called control effort.

Control effort means: how hard should the robot correct itself right now?

Student version: PID is like a coach that keeps saying, "You are too far left, move right a little."
public class PIDController {
    private double kp;
    private double ki;
    private double kd;
    private double accel;
}

2. The Most Important Word: Error

The controller starts by measuring the mistake.

error = target - current

If the target is 100 and the current value is 70, the error is 30. The robot still needs to move 30 units.

public double update(double current, double target) {
    double error = target - current;
    double dT = elapsedTime.seconds();
}
If error is big, the robot usually needs a bigger correction. If error is near zero, the robot is close.

3. P, I, and D Are Three Kinds of Help

PID combines three correction ideas. Each one looks at the mistake in a different way.

P

Present mistake

"How far away am I right now?"

I

Past mistakes

"Have I been wrong for a while?"

D

Speed of change

"Am I approaching too fast?"

output = P + I + D
Source: the final output combines the three terms in PIDController.java lines 58-59.

4. P Term: Proportional

The P term is the easiest one: multiply the current error by kp.

pTerm = kp × error

If the error is bigger, P pushes harder. If the error is smaller, P pushes softer.

// Calculate Proportional term
double pTerm = kp * error;

5. I Term: Integral

The I term adds up error over time. It helps when the robot keeps being a little bit wrong.

integralSum += error × dT
// Calculate Integral term
integralSum += error * dT;
double iTerm = ki * integralSum;

Imagine a bucket collecting tiny mistakes. If the bucket fills up, the controller adds extra correction.

I is useful, but too much I can make the robot overshoot because the bucket gets too full.
Source: I term is calculated in PIDController.java lines 50-52.

6. D Term: Derivative

The D term looks at how quickly the error is changing.

derivative = (error - lastError) ÷ dT

If the robot is rushing toward the target too quickly, D can help slow the correction down.

// Calculate Derivative term
double derivative = (error - lastError) / dT;
double dTerm = kd * derivative;
Source: D term is calculated in PIDController.java lines 54-56.

7. Add the Three Corrections

After P, I, and D are calculated, the controller adds them together.

output = pTerm + iTerm + dTerm

This output is the controller's answer. It may become motor power, turn power, or another correction value.

// Combine terms for the final output
double output = pTerm + iTerm + dTerm;

9. Acceleration Limit: Do Not Jump Too Fast

The controller also limits how quickly the output can change.

dV = dT × accel
double dV = dT * accel;
if((output - lastOutput) > dV){
    output = lastOutput + dV;
} else if ((output - lastOutput) < -dV){
    output = lastOutput - dV;
}

10. Remember Values for Next Time

After calculating output, the controller saves information for the next loop.

lastError = error;
elapsedTime.reset();
lastOutput = output;
return output;
  • lastError helps calculate D next time.
  • elapsedTime.reset() starts timing the next loop.
  • lastOutput helps smooth the next output.
Source: saved values and return are in PIDController.java lines 74-77.

11. Reset Means Start Fresh

Sometimes the robot reaches a target or starts a new task. Then the controller should forget old accumulated error.

public void resetIntegralSum() {
    integralSum = 0.0;
}

public void reset() {
    lastError = 0.0;
    integralSum = 0.0;
    elapsedTime.reset();
}
Reset is like erasing the scratch work before solving a new math problem.
Source: reset methods are in PIDController.java lines 80-94.
