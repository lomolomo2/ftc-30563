TankControllerTest: Robot Navigation, Step by Step

A 7th-grade friendly animated lesson for explaining how the autonomous program drives a tank-drive robot through five target positions.

1. What This Program Does

TankControllerTest is an autonomous OpMode. That means the robot follows instructions after the driver presses START.

Think of the robot like a student walking to marked spots on a gym floor. The program says:

  1. Start at position zero.
  2. Drive to Target 1.
  3. Turn and move through Targets 2, 3, 4, and 5.
  4. Stop when the path is complete.
Big idea: the code repeats a simple question: Am I at the target yet? If yes, it moves to the next target.

3. The State Machine

A state machine is a checklist where the robot only does one job at a time.

When one job is finished, the robot changes to the next state.

WAITINGBefore moving
TARGET 1Drive to first spot
TARGET 2Turn to 90 degrees
TARGET 3Drive upward
TARGET 4Turn around
TARGET 5Drive left
AT TARGETStop motors

Big idea: the robot does not try every instruction at once. It follows the current state.
Source: state names are declared in TankControllerTest.java lines 30-38.

4. Target Positions Are Like Map Coordinates

The targets are written as Pose2D objects. A pose means:

  • X: side-to-side or forward map distance
  • Y: the other map distance
  • Heading: where the robot points, in degrees

The distance unit is millimeters. The square size is 400.0 mm.

TARGET_1 = (400, 0, 0 degrees)
TARGET_2 = (400, 0, 90 degrees)
TARGET_3 = (400, 400, 90 degrees)
TARGET_4 = (400, 400, -180 degrees)
TARGET_5 = (0, 400, -180 degrees)

5. Setup Before START

Before the robot moves, the code connects to real hardware by name. These names must match the Robot Controller configuration.

leftDrive = hardwareMap.get(DcMotor.class, "motorLeft");
rightDrive = hardwareMap.get(DcMotor.class, "motorRight");

Then it sets motor behavior and direction:

  • BRAKE helps the motors resist rolling when power is zero.
  • The left motor is reversed because left and right motors face opposite directions on many drivetrains.
Source: hardware mapping and motor setup are in TankControllerTest.java lines 53-60.

6. PID Controllers Are Correction Helpers

A PID controller is a helper that answers: How hard should I correct my mistake?

  • The distance controller helps the robot move closer to the target.
  • The heading controller helps the robot point the right direction.
  • The TankController turns those corrections into left and right motor power.
distanceController = new PIDController(...);
headingController = new PIDController(...);
tankController = new TankController(...);
Imagine walking to a door while a friend gives corrections:

"A little forward."
"Turn right a bit."
"Slow down, you're close."
Source: PID and tank controller setup are in TankControllerTest.java lines 62-64.

7. Pinpoint Is the Robot's Map Sensor

The code uses a goBILDA Pinpoint odometry computer named odo. It tracks where the robot is.

  1. Get the sensor from hardware map.
  2. Configure the sensor.
  3. Set the starting position to X=0, Y=0, Heading=0.
odo = hardwareMap.get(GoBildaPinpointDriver.class, "odo");
configurePinpoint(odo);
odo.setPosition(new Pose2D(... 0, 0, ... 0));

8. The Main Loop Repeats Fast

After START, the program enters a loop. This loop runs again and again while the OpMode is active.

while (opModeIsActive()) {
    odo.update();
    switch (stateMachine) {
        ...
    }
}

Each loop does three key jobs:

  1. Update the robot's position.
  2. Check the current state.
  3. Tell telemetry what is happening.
The robot is not doing one giant move. It is making many tiny decisions very quickly.
Source: loop and odometry update are in TankControllerTest.java lines 80-83.

9. DriveTo: The Important Question

For each target, the code calls tankController.DriveTo(...).

That method returns:

  • false: "I am still moving."
  • true: "I reached the target and held it long enough."
if (tankController.DriveTo(... TARGET_1 ...)) {
    telemetry.addLine("at position #1!");
    tankController.reset();
    stateMachine = StateMachine.DRIVE_TO_TARGET_2;
}

11. Telemetry Is the Robot's Voice

Telemetry sends messages to the Driver Station so humans can see what the robot thinks is happening.

Pose2D pos = odo.getPosition();
String data = String.format(... X, Y, H ...);
telemetry.addData("Position", data);
telemetry.update();

The code reports:

  • X position
  • Y position
  • Heading angle
When debugging, telemetry is like asking the robot, "Where do you think you are right now?"
Source: telemetry position output is in TankControllerTest.java lines 136-142.

12. Final Stop

When the robot reaches the final target, it changes to AT_TARGET. Then both motors are set to zero power.

case AT_TARGET:
    leftDrive.setPower(0.0);
    rightDrive.setPower(0.0);
    telemetry.addLine("Tank controller test complete");
    break;
The final state is important because a robot should always have a clear "done" behavior.
Source: final stop behavior is in TankControllerTest.java lines 129-133.
